1. Introduction

GunGame AMXX 3++ is an independent continuation of Avalanche’s GunGame AMXX 2.13c for Counter-Strike 1.6 and Condition Zero. Players advance through a configurable weapon sequence by earning kills. Completing the final level wins the match. Teamplay shares progression within a team; deathmatch allows players to respawn instead of waiting for the next round.

The pur3gaming Edition aims to preserve the original gameplay while improving compatibility, statistics and database handling.

2. What is new in 3++

  • One plugin contains both local-file and MySQL/MariaDB statistics backends, selected through configuration.
  • Threaded SQL operations for player prefetch, rankings, statistics writes, streaks and match snapshots reduce synchronous work during gameplay. One synchronous connection call remains for charset-aware escaping.
  • Player statistics caches use identity and generation checks to reject stale callbacks after disconnects or slot reuse.
  • Deferred handicap handling coordinates late statistics results with player spawn state.
  • SQL connection probes and reconnect handling support recovery from database failures without silently switching to local files.
  • YaPB fake SteamID detection uses FakeMeta without a separate bridge module.
  • UTF-8 database connections use utf8mb4; winner snapshots support optional history and timestamp-specific web results.
  • New server diagnostics: gg_info, gg_status and category-specific debug controls.
  • Companion PHP dashboard provides rankings, player profiles, latest match results and optional live server status.

Database architecture and reliability

  • Threaded statistics, streak persistence, ranking prefetch and winner snapshots; player identity, UserID, slot and generation validation protect against stale callbacks.
  • Asynchronous handicap ranking with deferred initialization, bounded retry and level-1 fallback; spawn finalization is separated from handicap processing.
  • Staged SQL initialization: charset, statistics, streaks and winner MOTD. Player caches load after successful initialization.
  • Asynchronous reachability probes and automatic reconnect scheduling at 15-second intervals; overlapping initialization and reconnect attempts are guarded.
  • Central SQL error handling and charset-aware escaping; UTF-8 player names are refreshed even without a points increase, with timestamp protection.
  • One synchronous SQL connection call remains for the escaping handle. This is not a guarantee of zero main-thread blocking.

3. Requirements and installation

Development targets: AMX Mod X 1.10, ReHLDS, ReGameDLL and YaPB. These are development targets, not a certified compatibility matrix. The source uses AMX Mod X, AMX Misc, FakeMeta, FakeMeta Utilities, CStrike, HamSandwich and SQLX includes. MySQL support is needed for the SQL backend; local-file mode does not require a working SQL connection.

  1. Back up existing GunGame configuration and statistics, including SQL tables if applicable.
  2. Compile addons/amxmodx/scripting/gungame.sma locally with the AMX Mod X 1.10 compiler and matching standard includes (including SQLX). On Linux, run ./amxxpc gungame.sma -ogungame.amxx from the scripting directory; on Windows, use amxxpc.exe gungame.sma -ogungame.amxx. Check for compilation errors. No compiled AMXX plugins are supplied.
  3. Install the compiled gungame.amxx in addons/amxmodx/plugins/ and enable it in addons/amxmodx/configs/plugins.ini (avoid duplicate entries).
  4. Install the matching release configuration, dictionary addons/amxmodx/data/lang/gungame.txt and supplied sound assets in their intended locations.
  5. Configure addons/amxmodx/configs/gungame.cfg and, if used, gungame_teamplay.cfg.
  6. Restart the server and verify amxx plugins, amxx modules and gg_info.

Do not assume that an existing database schema is automatically migrated. Test upgrades on a copy first.

3.1 AMX Mod X preparation

Install AMX Mod X with its Counter-Strike addon. Check the installed version using amxx version and check the CStrike module using amxx modules. The original 2.13 documentation required AMXX 1.80 or later; this is a historical requirement, not a verified minimum for 3++. Use the tested AMXX 1.10 environment for this release. See AMX Mod X for installation packages.

3.2 Release files

Extract the matching release into the game directory (cstrike/ or czero/), preserving its directory structure. Enable the plugin in addons/amxmodx/configs/plugins.ini:

; Custom plugins
gungame.amxx

Unlike 2.13, 3++ does not require separate SQL and flat-file archives. Select gg_stats_backend 0 for local files or gg_stats_backend 1 for SQL. See statistics setup and SQL schema.

3.5 Random spawn locations and CSDM

Place map-specific spawn files at addons/amxmodx/configs/csdm/<map>.spawns.cfg, for example de_dust2.spawns.cfg. Existing CSDM spawn packs can be used without loading CSDM itself. GunGame reads up to 128 spawn positions per map.

gg_dm 1
gg_dm_spawn_random 2

Mode 0 disables random relocation; mode 1 uses custom spawn positions or ordinary map spawn entities when no custom file exists; mode 2 requires loaded custom spawn positions. If using external CSDM instead, set gg_dm 0 and disable CSDM weapon selection (csdm_equip.amxx) to avoid competing weapon management.

CSDM is optional and its plugin list is shipped as disabled-csdm.ini. To use CSDM, obtain or compile its plugins, verify the matching module, rename the list to plugins-csdm.ini, disable csdm_equip.amxx and set gg_dm 0 before restarting.

3.6 Final checks

Review the CVAR reference and FAQ, then verify plugin status, map rotation, weapon progression and statistics persistence. Source: original installation guide, adapted for 3++.

8. Web statistics and winner MOTD

The optional companion web application uses PHP and PDO MySQL to read the SQL tables. It provides solo/team rankings, search, server filters, player profiles, streak records and latest match results. Live server status is loaded independently when enabled.

  1. Deploy the supplied web directory to a PHP-capable web server.
  2. Configure config.php from the supplied example, matching the database and table names. Use a read-only database account for the website.
  3. Configure your own site URL, timezone and optional game-server settings. Verify the dashboard and language files.
  4. For the web winner screen, set gg_winner_motd to the deployed MOTD URL (SQL backend required). Keep the URL within the source’s 63-character limit and do not append query parameters.
Setting / command Description
gg_winner_motd 0 Disable winner screen.
gg_winner_motd 1 Use built-in winner screen (default).
gg_winner_motd 2 Store SQL snapshot without opening the external web page; built-in screen remains available.
gg_winner_motd https://example.tld/motd.php Use the external winner screen after successful snapshot write.

The plugin supplies server address, player slot, language and match timestamp to the web MOTD. History mode increases database storage; plan retention separately.

Companion web release

The web development changelog records the following features. Deploy the matching web package; the plugin alone does not install these components.

  • Responsive dashboard, top-three podium, profiles, solo/team rankings, search, sorting, pagination, server filtering and automatic language discovery (English and German).
  • GameQ live monitoring: server name, address, game type, GunGame version, online status, human/bot counts and capacity. Cached queries and configurable refresh; no RCON credentials required.
  • Map timeline: previous, current and next map, game-specific preview directories, fallback image and synchronized countdown where data is available. Previous-map information can use cached observations and match snapshots.
  • Steam connection links and optional HLstatsX/PsychoStats links from validated server rules or per-server configuration.
  • Configurable site title, URL and timezone (UTC default), canonical URLs, Open Graph and Twitter/X metadata, social preview and credits page. API and MOTD are excluded from indexing.
  • Local assets, separated API, includes, vendor, languages and cache directories; third-party notices and license files. Map images with unclear redistribution rights are excluded from the public package.

Deployment safety

Keep configuration credentials and cache files out of public release archives. Restrict HTTP access to sensitive configuration and cache paths. Use a read-only database account and configure the optional game-server allowlist where available. Validate outbound server queries and external links; do not expose RCON credentials.

9. Compatibility and testing

GunGame includes its own deathmatch implementation and recognizes the CSDM active CVAR in gameplay paths. When combining with CSDM, coordinate respawn and weapon-management settings to avoid conflicts. Test the actual plugin combination before production use.

YaPB fake SteamID handling observes yb_enable_fake_steamids and authentication events. Test bot identity and ranking behavior with your installed YaPB version.

Developers should use the supplied SMA and matching AMX Mod X includes. No new public native API is documented here. SQL callbacks and internal cache structures are implementation details.

Development and runtime testing

GunGame AMXX 3++ has undergone extensive development and runtime testing, including asynchronous SQL processing, statistics persistence, ranking and handicap handling, YaPB integration, UTF-8 support and database connection recovery. The development test environment included Counter-Strike 1.6, ReHLDS, AMX Mod X 1.10.0.5217, CSDM 2.1.3d, YaPB 4.8 and MariaDB.

Testing included map changes, warmup, player reconnects, slot reuse, simulated handicap failures, winner MOTD and web export. Database recovery was observed after connectivity was restored and a map change occurred. These results describe the accumulated development testing, not exhaustive validation of every configuration or failure scenario.

Operational considerations

One synchronous SQL connection call remains for charset-aware escaping. Match persistence is not fully transactional: interrupted writes may be partial and are not automatically replayed. Before upgrading an existing installation, back up configuration files and databases and verify the upgrade in a test environment.

13. SQL setup and schema reference

Use a dedicated MySQL/MariaDB database and account. Create the database first. Grant the game account SELECT, INSERT, UPDATE, DELETE and CREATE on that database; review any additional permissions against the actual deployment. The web account needs SELECT only. Never publish credentials. Restrict network access to the game and web hosts.

Connection examples

gg_stats_backend 1
gg_stats_mode 2
gg_sql_host ""
gg_sql_user ""
gg_sql_pass ""
gg_sql_db ""

All four empty fields select central AMXX sql.cfg. Any nonempty field selects custom configuration; host, user and database must then be supplied. No per-field fallback. MySQL affinity is forced regardless of amx_sql_type.

gg_sql_host "db.example.tld"
gg_sql_user "gungame"
gg_sql_pass "REPLACE_WITH_SECRET"
gg_sql_db "gungame"

Restart or change map after backend changes. Check gg_info, gg_status and AMXX logs. Do not enable fault injection on production.

Snapshot and history

Use gg_winner_motd 2 for SQL snapshots or a short external MOTD URL. The external request includes s (server), i (slot), l (language), t (timestamp). History 0 deletes older snapshots for the server before inserting; history 1 retains them. Do not assume history is automatically pruned. Keep backups and plan retention. The timestamp key has second precision.

Upgrade checklist

Back up all tables and configuration. Compare SHOW CREATE TABLE output with the new schema, especially the snapshot primary key and unsigned columns. CREATE TABLE IF NOT EXISTS does not itself migrate an existing table. Test on a separate database before changing production. Do not import legacy rows blindly: verify point semantics, metadata and identity mode. No automatic migration procedure is certified here.

Diagnostic levels

The shared helper enables a message when gg_debug, gg_debug_sql or its category meets the requested threshold. Levels 2 and 3 occur in the source; 0 is the production default. Fault and delay injection are separate test controls and must remain zero in production.

amx_gungame_restart [delay] [full] 2.13c Restarts GunGame. You can optionally specify a delay, in seconds. If full, reloads config and everything. Requires ADMIN_BAN (or flag d) access to use.
gg_reloadweapons 2.13c Reloads the weapon order and the kills per level from the cvars. This must be used if either of those two things are changed mid-game. Can only be called by server.

Since version 2.13, GunGame has optional built-in SQL stats storage. It's generally much faster and more efficient than the flat-file alternative. If you wish to use it, simply compile gungame.sma with the #define SQL line near the top of the file uncommented. If you download the "SQL stats" package, this has already been done for you. (To be clear: download only the "flat-file stats" package or only the "SQL stats" package, depending on the method of stats storage you wish to use.)

You can go here to convert your old flat-file stats files into SQL queries which you can use to populate your stats database.

15. Frequently asked questions

The following answers apply to GunGame AMXX 3++ 3.0.0-rc3. Historical answers are preserved separately below.

How can I receive the next weapon immediately?

Enable turbo mode in gungame.cfg:

gg_turbo 1

See the CVAR reference for related settings.

Do I need separate SQL and flat-file versions of GunGame?

No. The same 3++ plugin supports both backends. Set gg_stats_backend 0 for local files or gg_stats_backend 1 for SQL in gungame.cfg. Change map or restart the server after changing the backend. See installation.

Why is GunGame not running?

Check that gungame.amxx is enabled once in plugins.ini, that the matching dictionary and assets are installed, and that gg_enabled is set to 1. Run these commands in the server console and inspect the AMXX error logs:

amxx version
amxx plugins
amxx modules
gg_info
gg_status
Where does GunGame read its configuration?

GunGame searches the AMXX configuration directory first, then the game directory, for gungame.cfg and gungame_teamplay.cfg. Avoid maintaining conflicting copies. See per-map configuration.

How do I configure a fixed weapon sequence?

Set gg_weapon_order to a comma-separated sequence of weapon names. Clear alternative sequences gg_weapon_order1 through gg_weapon_order10 if random alternatives are not wanted.

gg_weapon_order "glock18,mp5navy,ak47,m4a1,knife"
gg_kills_per_lvl 2

Use gg_reloadweapons in the server console to reload weapon order and kills per level. Prefer changing the sequence between matches.

How do I disable warmup?

Set gg_warmup_timer_setting 0 in the configuration. The normal compiled default is 60 seconds. gg_warmup_weapon selects the warmup weapon.

How do I enable automatic respawning? 
gg_dm 1
gg_dm_spawn_delay 3.0
gg_dm_sp_time 1.0

These settings enable GunGame deathmatch, a three-second respawn delay and one second of spawn protection. Avoid running two competing respawn systems.

Why do players respawn at normal map spawn points?

Check gg_dm_spawn_random and the file addons/amxmodx/configs/csdm/<map>.spawns.cfg. Mode 0 disables random relocation; mode 1 permits ordinary map spawn positions as a fallback; mode 2 requires custom positions. GunGame reads up to 128 custom positions per map. CSDM itself is not required to read these files.

Can I use an external CSDM installation?

Yes, as a configuration option. Disable GunGame deathmatch with gg_dm 0 if CSDM manages respawning. Disable competing weapon selection, such as csdm_equip.amxx. Verify the combination on your server; not every CSDM build has been tested.

How can I use a separate GunGame map rotation?

Create addons/amxmodx/configs/gungame_mapcycle.cfg with one installed map per line. See the mapcycle search order for alternative filenames and locations.

de_dust2
de_inferno
cs_office
How do I switch to team progression?

Configure gg_teamplay 1 or use the authorized admin command amx_gungame_teamplay 1. Teamplay shares progression within each team. Review gungame_teamplay.cfg and gg_stats_split before switching modes.

How can an administrator adjust a player level?

Use amx_gungame_level with a target and an absolute or relative level. For example:

amx_gungame_level #12 +1
amx_gungame_level #12 5

Here #12 is an example UserID, not a player slot. The command requires ADMIN_BAN access. See administration.

Why are rankings disabled or unavailable?

Check gg_stats_mode: 0 disables statistics, 1 ranks by wins and 2 ranks by points. Verify the selected backend. In SQL mode check module availability, credentials, table access and AMXX logs. SQL rankings may also be temporarily unavailable while asynchronous data is loading.

How do I configure a MySQL or MariaDB database? 
gg_stats_backend 1
gg_stats_mode 2
gg_sql_host "localhost"
gg_sql_user "gungame"
gg_sql_pass "CHANGE_ME"
gg_sql_db "gungame"

These are placeholders. Create the database and grant the game-server account the required permissions. GunGame can also use central AMXX SQL settings. See the SQL setup and schema. Never publish actual credentials.

What happens if the SQL connection fails?

GunGame does not silently switch to local statistics. Gameplay and database availability are separate concerns. Failed writes are not guaranteed to be recovered or replayed. Restore connectivity, inspect the logs and change map if necessary to reinitialize SQL. Do not assume that same-map recovery or lossless persistence is guaranteed.

Can I reuse an older GunGame database?

Back up all existing tables and test on a copy. Missing tables can be created by the plugin, but this is not a guarantee of automatic migration of every older schema. Compare columns, keys and table definitions with the current schema before deployment.

How are players identified in statistics?

gg_stats_ip 0 uses authentication IDs, 1 uses IP addresses and 2 uses player names. The source also accepts -1 as name-based identification. Prefer stable authentication IDs; changing identification mode can create separate records for the same player.

Can YaPB bots have individual statistics?

With gg_stats_ip 0 and YaPB fake SteamIDs enabled (yb_enable_fake_steamids 1), GunGame can use observed bot authentication IDs. It checks the current UserID to avoid reusing a previous occupant’s cached identity. If no fake ID is observed, the original authentication behavior applies. Check gg_ignore_bots and gg_status when investigating bot statistics.

Why is a player timestamp updated when joining?

gg_stats_refresh_on_join controls this policy: 0 disables it, 1 enables it for either backend, and 2 enables it only for SQL (default). This refresh is separate from awarding match points.

Why have inactive players disappeared from the rankings?

Check gg_stats_prune. Its compiled default is 2592000 seconds (30 days). Review the pruning policy and back up statistics before changing retention settings.

Why does a joining player not receive handicap immediately?

Handicap depends on gg_handicap_on, match state and ranking eligibility. With SQL and top-player exclusion enabled (gg_top10_handicap 0), ranking data may need to arrive asynchronously. A pending decision is not necessarily a failure. Inspect gg_status and temporary handicap diagnostics.

How do I enable the web winner screen?

Deploy the matching PHP web package, configure its database connection and select SQL mode in GunGame. Set the winner MOTD URL, for example:

gg_winner_motd "https://example.tld/motd.php"

Use your own URL, no query parameters, and keep it within 63 characters. The external screen depends on a successful SQL snapshot write. See web setup.

Can I store match snapshots without opening a web page?

Yes. With SQL initialized, gg_winner_motd 2 requests snapshot storage while retaining the built-in winner screen. Set gg_winner_motd_history 1 to retain historical snapshots instead of replacing the server snapshot. Plan database retention separately.

Why does the website show no players or match results?

Verify that the game server uses SQL, that the web configuration points to the same database and table names, and that the web account can read them. Match results require a stored winner snapshot. Live server queries and database rankings are separate features. Use a read-only web database account.

Does gg_status execute database queries?

No. It is a read-only server-console diagnostic command that reports existing runtime state, including player slots, UserIDs, levels, weapons, ranks, cache state, pending handicap and generation. It does not issue additional SQL queries.

How do I troubleshoot SQL without recompiling?

Enable the relevant runtime diagnostics temporarily:

gg_debug_sql 2
gg_debug_ranking 2
gg_debug_handicap 2

Inspect AMXX logs, then return the settings to 0. Keep gg_debug_handicap_fault and gg_debug_handicap_delay at 0 in production; these are development test controls. See runtime diagnostics.

Does asynchronous SQL eliminate every possible server lag?

No. Threaded queries reduce blocking from database operations, but initialization and some SQL operations still use synchronous paths. Network latency, server CPU load, other plugins and client connectivity can also affect gameplay. Diagnose the actual bottleneck rather than assuming every lag is caused by GunGame.

Which server environments are supported?

The development targets are AMX Mod X 1.10, ReHLDS, ReGameDLL and YaPB. The plugin is intended for Counter-Strike and Condition Zero environments. This is not a certification of every engine, mod or third-party plugin combination. See compatibility and testing.

15.1 Original FAQ archive

Source: Original FAQ (17 questions). Historical answers may refer to older releases.

The following FAQ entries originate from the GunGame AMXX 2.13 documentation by Avalanche. Historical requirements and compatibility statements have not been revalidated for this release. See the current installation and configuration sections for release-specific information.

1. How do I make it so players receive their next weapon instantly upon level up?

Set gg_turbo to 1 in your gungame.cfg file. Read through the Gameplay Cvars section of the Cvar List page for more information.

2. How do I get players to respawn at random locations?

Refer to the Random Spawn Points step of the Installation page. Also read the Deathmatch Cvars section of the Cvar List page. It's particularly important to understand the difference between using gg_dm_spawn_random 1 and gg_dm_spawn_random 2.

3. How do I give individual weapons specific kill requirements?

In the gg_weapon_order cvar, add :X to the end of a weapon name to require X kills for that weapon. For example:

gg_weapon_order "glock18,deagle:5,mp5navy:3,m4a1:4,awp:1,m249,knife:2"

If there is no specific goal attached to that weapon, it is assumed to be whatever gg_kills_per_lvl is, except for the grenade and knife levels where the default is 1. Read through the Gameplay Cvars section of the Cvar List page for more information.

4. How do I randomize the weapon order?

You can make use of the gg_weapon_orderX cvars in your gungame.cfg file. Starting with gg_weapon_order1 and working your way towards gg_weapon_order10, set each of them to one of the possible weapon orders that you want to use, in the same format as the regular gg_weapon_order cvar. You don't have to use all 10 random weapon orders if you don't want to: leave any unused gg_weapon_orderX cvars at the end blank.

If you're using random weapon orders, the value of your original gg_weapon_order cvar doesn't matter, as it will be changed at every map to one of the random choices.

The random weapon order sequence is randomly shuffled and then played in that shuffled order. Once all the random weapon orders have been played, the sequence is reshuffled. This guarantees that every random weapon order is played with the same frequency.

5. How do I set map-specific GunGame configs (e.g. weapon orders)?

You can achieve this with AMXX's map config file feature. For example, creating a file named addons/amxmodx/configs/maps/de_dust2.cfg with the below contents would force the specified weapon order and disable any other possible random weapon orders while playing de_dust2.

de_dust2.cfg:

gg_weapon_order "deagle,mp5navy,ak47,awp,knife"
gg_weapon_order1 ""
gg_weapon_order2 ""
gg_weapon_order3 ""
gg_weapon_order4 ""
gg_weapon_order5 ""
gg_weapon_order6 ""
gg_weapon_order7 ""
gg_weapon_order8 ""
gg_weapon_order9 ""
gg_weapon_order10 ""

Note that you can use map config files to override any cvars on a per-map basis.

6. How can I get GunGame stats onto my website?

Check out the SQL Stats page.

7. How does teamplay mode work?

Teamplay mode, introduced in GunGame AMXX 2.10, can be activated by setting gg_teamplay to 1 (or 2 if you want it to be randomly enabled). During teamplay mode, it's the Terrorist team versus the Counter-Terrorist team.

Instead of players leveling up individually, they level up as a team. When you kill someone, your kill gets added to your team's pool of kills. Once your team reaches the kill requirement (which is the individual kill requirement multipled by the number of players on that team), your entire team levels up.

Level steals only net your team the individual kill requirement for that level. Also, the amount of points that you get when your team wins is based on how much time you spent on that team (percentage-based, using the time you spent on the winning team versus the time you spent on the losing team).

8. Is there any way to disable the round timer?

GunGame doesn't include any feature to disable the round timer. However, there are other plugins and modules that can do that such as Counter-Strike Deathmatch (CSDM) by BAILOPAN. For details on how to run GunGame and CSDM in unison, see Can I run Counter-Strike Deathmatch (CSDM) with GunGame?.

9. I installed everything but GunGame just doesn't run! Why?

Verify that you have AMXX 1.80 or later and the AMXX Counter-Strike Addon. Read through the Installing AMXX step of the Installation page for verification instructions.

If the plugin still doesn't load after verifying your AMXX installation, you can try posting on the AlliedModders forums for help.

Your forum post should include the diagnostic information listed below. Before gathering this information, you should enable debug mode on the plugin. You can do this by editing your plugins.ini file: replace gungame.amxx with gungame.amxx debug.

Diagnostic information:

  1. The console output of amxx plugins, amxx modules, and meta list.
  2. The contents of your addons/amxmodx/configs/plugins.ini and gungame.cfg files.
  3. Anything in the server console that is printed during server startup, such as "Plugin failed to load: ...".
10. How come some weapons don't get any extra backpack ammo, or the game crashes after a specific level (usually the rifles)?

This only happens when you're running a modded version of Counter-Strike. The most common mods that can cause this are: non-Steam Counter-Strike, zBot, a cracked HLDS, and Counter-Strike 1.5. These mods are unsupported by AMXX and by GunGame. There is no workaround except not using these mods.

11. Why are some kills reported as suicides instead of kills?

Usually this means that you're running another plugin that changes how much damage a player does. For example, Warcraft 3 Mod or HE Damage Multiplier. Behind the scenes, deaths caused by these plugins are actually suicides and the plugins modify the death messages to hide that fact. Unfortunately these types of plugins aren't compatible with GunGame because of how they work.

12. Why does all the GunGame text appear as ML_NOTFOUND ?

This might mean that your dictionary file (addons/amxmodx/data/lang/gungame.txt) is missing or broken. Try redownloading it to fix the problem.

If you make any manual changes to the dictionary file, you must save it UTF-8 encoded without the byte-order mark (BOM). Only some text editors have that capability. Notepad++ is one such text editor.

13. Why does all the GunGame text appear as squares?

This means your AMXX language was changed to a language that doesn't have translations for GunGame. To revert your AMXX language to English, type this in console:

Console:

setinfo "lang" "en"
14. Can I run Counter-Strike Deathmatch (CSDM) with GunGame?

Yes, CSDM is fully compatible with GunGame. To prevent GunGame and CSDM from interfering with each other, you'll want to make these configuration changes:

  1. Turn off GunGame's deathmatch functionality by setting gg_dm to 0 in your gungame.cfg.
  2. Turn off CSDM's weapon menu by disabling the csdm_equip.amxx plugin.
15. Can I run Warcraft 3 or SuperHero Mod with GunGame?

You can try, but those plugins probably won't work well with GunGame. Those plugins cause players to do extra damage (see Why are some kills reported as suicides instead of kills? for why this is a problem) and sometimes give players extra weapons, which conflicts with GunGame's functionality.

16. Can I use weapon mods like the RPG or Flamethrower with GunGame?

Unfortunately not. While these mods may still technically work with GunGame, you cannot add them to GunGame's weapon order. This is because of the difficulties associated with integrating each of these plugins into GunGame's existing system.

17. I'm running Deagles' Map Management (DMM), so why aren't the map votes coming up?

There are a couple things that could be going wrong. First, make sure you have gg_vote_setting set to 1 or higher in your gungame.cfg file (see the Basic Cvars section of the Cvar List page for more information).

Next, verify that you don't have a gungame_mapcycle.txt file in the mod directory (cstrike/ or czero/) or in your addons/amxmodx/configs/ directory. If you're using a GunGame map cycle file then no votes will occurr.

If it still doesn't work, verify that your DMM plugin file is named correctly. If you're running DMM 2.30b the plugin file must be named deagsmapmanage230b.amxx. If you're running any other version of DMM, the plugin file must be named deagsmapmanager.amxx.

If there are still no votes occurring, make sure you're running DMM in voting mode and not in cycle mode. You can set DMM to voting mode via the dmap_votemode command (requires high admin access, or you can run it in the server console). If it says "Unknown command" then DMM isn't even running in the first place.

After all that, if still no votes come up, monitor your server console around the time that the votes should be occurring to check for messages from DMM which could provide some insight.
